# PRISM trend base: the seed and how it is loaded

**Base:** 51 drivers (release 2.12.0; September 2026 senior-partner review, owner ruling O10; Toilet Care split, owner ruling O13) | **Module:** `pulse/seed_trends.py` (generated) | **Inputs:** `data/trend_base_2026-09/`

## What the seed is

`pulse/seed_trends.py` holds the trend base as Python `Trend` rows plus a `SOURCE_URLS` table (graded sources per driver). It is **generated**, never hand-edited:

```
data/trend_base_2026-09/core_set_51_v4.json   the reviewed core set (descriptions, direction,
                                              probability, GP1 share, onset, peak, curve,
                                              confidence, category / regional / value-chain
                                              exposures, uncertainty score, graded sources,
                                              mechanism, review notes, absorbed base codes).
                                              v4 = v3 plus the Toilet Care exposure column
                                              (owner ruling O13, 2.12.0): 37 of the 51 drivers
                                              inherit their HSC score unchanged, 14 deviate
                                              with a written reason.
data/trend_base_2026-09/verdicts_99_v1.json   the disposition of every code of the previous
                                              99-trend base (KEEP / MERGE INTO / SUBSTITUTE /
                                              DELETE / NEW) with the review's reason
        │
        ▼  python3 scripts/generate_seed_from_core_set.py
pulse/seed_trends.py        51 Trend rows + SOURCE_URLS + the E1 credibility gate + CLI
data/trendCodeMap.ts        51 live display codes + 65 retired codes with merged-into pointers
```

`python3 scripts/generate_seed_from_core_set.py --check` verifies that the committed outputs equal the generator output; `tests/test_trend_base_2026_09.py` runs that check in CI and locks the population, the value ranges, the code map partition and the replacement script.

## What every row carries

- `probability` 1-5, `gp1_pct_affected` (share of the category's 2025-35 GP1 pool the driver can move at full materialisation), `start_year` (onset gate, F11), `peak_year`, `diffusion_curve`, `confidence` (display-only metadata, F3).
- `uncertainty` 0-5 (owner ruling O7, 2.11.0): one score per driver that sets the Beta-prior concentration (24/16/10/6/4/3, mean unchanged) and the per-driver peak-year jitter (0/1/1/2/3/4 years). A trend without a score behaves exactly as in 2.10.0.
- `category_exposure` (13 categories, 0-5) and `regional_exposure` (4 regions, 0-5): independent, mechanism-only dimensions (owner ruling O9). The taxonomy has 13 categories since owner ruling O13 (2.12.0) split Toilet Care (`LHC: TOI`) out of Hard-Surface Cleaner, so the base carries 13 categories x 51 drivers = 663 category scores. Presence in a region enters the model through the cell weights (the gross-profit share of each category x region cell — 13 x 4 = 52 cells), not through the exposures. Since owner ruling O14 (2.12.0) the default matrix is an ESTIMATE of the HCB gross-profit mix rather than the equal 1/52 placeholder it replaced: it is generated by `scripts/build_estimated_cell_weights.py` into the record `data/cell_weights_estimated_v1.json` (`--check` in CI), every input carries a grade (B public reporting supports it / E defensible but unverified / G low-confidence guess), and it is **not Henkel P&L**. The flat grid stays selectable as `pulse.config.EQUAL_CELL_WEIGHTS`, and the real finance shares still override the default when they are passed to `run_50k_prod.py --cell-weights FILE` — O14 changed the fallback, not that route.
- `vc_exposure`: the editor's canonical 5/3/1 serialisation around the reviewed epicentre stage (the engine reads the epicentre only, O5).
- `sources`: graded S (primary: statute, filings, official statistics) / A (analyst research, major press) / B (trade press) with the publication month in `source_type`.
- `ai_suggested=False`, `user_override=False`: the reviewed base carries no provenance label (owner decision 2026-09-10); `ai_suggestion` holds the baseline snapshot (incl. the uncertainty score) that the multi-expert proposals layer compares against.

## How the base reaches a database

| Situation | Path |
|-----------|------|
| Fresh local SQLite (empty) | `python -m pulse --serve` and `pulse/api/state.py` seed automatically from `get_report_trends()` |
| Existing database on the 99-trend base (local SQLite, then Neon) | `python3 scripts/replace_trend_base.py` — archive-first (trends, exposures, sources, proposals to `data/archive/`), deletes the retired ids, writes the 51, restores the expert proposals of the kept ids, verifies, writes an audit-log entry. `--dry-run` reports only; `--postgres` is required to touch Neon. Run once per database by the owner. |
| Later edits to the reviewed JSON | change the JSON, re-run the generator, commit the regenerated files, then `POST /api/v1/trends/full-reseed` (admin) or the replacement script |

`POST /api/v1/seed` and `POST /api/v1/trends/sync` upsert the seed without deleting orphans; they are not the way to move a database from the 99 base to the 51 base.

After the replacement, re-run `scripts/run_50k_prod.py`: the first 2.11.0 run reports the mass replacement as a critical input-drift event by design (D19).

## Credibility gate (E1)

`assert_trend_credible` refuses to seed a driver without at least one source rated B- or better (tier ladder S > A > A- > B+ > B > B- > C > D > E). Every driver of the reviewed base passes with S/A/B sources only.

## Competitor profiles

`pulse/api/seed_data.py` still provides the 12 competitor profiles and the competitive-intelligence seed consumed by `pulse/api/routers/competitors.py`; its trend content is legacy and not loaded anywhere.
