Basic Usage Examples:

1. Scan for trends:

   suggestions = await scanner.scan_news_sources()

2. Detect scoring biases:
   calibrator = ScoreCalibrator()

   narrator = ScenarioNarrator()

4. Chat interface:
   chat = PulseChat()
   chat.set_context(context)
   answer = await chat.ask("Which categories face headwinds?")

ARCHITECTURE OVERVIEW
================================================================================

Layered Design:
  ┌─────────────────────────────────────────┐
  │      APPLICATION LAYER                  │
  │  War Room Dashboard / Power BI          │
  └────────────────┬────────────────────────┘
                   │
  ┌────────────────▼────────────────────────┐
  │      AI MODULES LAYER                   │
  │  TrendScanner                           │
  │  ScoreCalibrator                        │
  │  ScenarioNarrator                       │
  │  PulseChat                              │
  └────────────────┬────────────────────────┘
                   │
  ┌────────────────▼────────────────────────┐
  │      INFRASTRUCTURE LAYER               │
  │  LLM Providers (Claude, Azure, Ollama)  │
  │  Financial Data Firewall                │
  │  Configuration System                   │
  │  Audit Logging                          │
  └─────────────────────────────────────────┘

Data Flow:
  User Input
      ↓
   Firewall ✓ (check for financial data)
      ↓
   Process (LLM or Rule-based)
      ↓
   Output
      ↓
   Firewall ✓ (verify no financial data)
      ↓
   Return to User

Fallback Hierarchy:
  Tier 1: LLM-Powered (when API available)
    ↓ (if API fails)
  Tier 2: Statistical/Rule-Based (when LLM unavailable)
    ↓ (if rules fail)
  Tier 3: Null-Safe Defaults (when all else fails)

================================================================================
SECURITY MODEL
================================================================================

Financial Data Protection:
  • Blocks: GP1, GP2, NES, revenue, profit, margin, etc.
  • Enforces: Percentages only (e.g., "-3.2%", never "€50M")
  • Scans: All inputs before sending to LLM
  • Verifies: All outputs after receiving from LLM
  • Logs: All violations for audit trail

Credential Security:
  • Environment variables only (no hardcoded keys)
  • Azure Key Vault ready for production
  • Audit logging of all API calls
  • Token tracking for cost management

Data Privacy:
  • No user financial data stored locally
  • No company data persisted
  • Relative percentages only
  • Audit-clean logging

================================================================================
TROUBLESHOOTING REFERENCE
================================================================================

Issue: "Claude client not initialized"
  → Expected when API key not set
  → Modules work in fallback mode
  → Set ANTHROPIC_API_KEY if using Claude

Issue: "feedparser not installed"
  → Expected when pip dependencies missing
  → RSS scanning returns empty
  → Run: pip install feedparser

Issue: "Financial data in response"
  → Should NOT happen (firewall prevents it)
  → If warning appears, data is sanitized automatically
  → Check firewall configuration

Issue: Slow responses
  → Check if LLM API is available
  → Check network connectivity
  → Try rule-based fallback mode
